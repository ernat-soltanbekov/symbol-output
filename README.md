# symbol-output

Учебная консольная программа на Go: превращает текст в ASCII-рисунок и выводит
его в терминал или сохраняет в `.txt`. Цель проекта — освоить обработку аргументов,
работу с файлами, разделение кода на пакеты и проверку результата после записи.

Доступны три шрифта: `standard`, `shadow`, `thinkertoy`. Внешних Go-библиотек,
сети, ключей API и платных сервисов для работы программы не требуется.

## Установка и запуск

Нужен Go версии 1.22 или новее. Клонируйте репозиторий и перейдите в его каталог:

```sh
git clone https://01.tomorrow-school.ai/git/ysoltamb/symbol-output.git
cd symbol-output
go run . 'hello'
go run . --output=banner.txt 'hello' standard
cat banner.txt
```

Без `--output` рисунок попадает в стандартный вывод. Без названия шрифта
используется `standard`. При записи без `--verify` программа ничего не печатает.
Содержимое существующего обычного файла заменяется целиком.

```sh
go run . --output=first.txt 'First\nTest' shadow
go run . --output=special.txt '123 -> #$%' standard
go run . --output=toy.txt 'Hello 01!' thinkertoy
```

Одинарные кавычки сохраняют `$`, обратную косую черту и другие специальные
символы от обработки оболочкой. Принимаются печатные ASCII-символы с кодами
32–126: латинские буквы, цифры, пробел и знаки. Русские буквы, emoji, табуляция,
CR и другие управляющие символы возвращают понятную ошибку без изменения файла.

И буквальная пара `\n`, и настоящий LF означают перенос текста. Каждая строка
непустого ввода, включая пустую строку между переносами или после последнего
переноса, занимает **ровно 8 строк рисунка**. Например, `'A\n\nB'` — 3 текстовые
строки, то есть 24 строки рисунка; `'\n'` — 16. Полностью пустой аргумент `''`
создаёт пустой файл: 0 текстовых строк, 0 байт.

## Аргументы

```text
Usage: go run . [OPTION] [STRING] [BANNER]
EX: go run . --output=<fileName.txt> something standard
```

Флаг записи принимается строго в форме `--output=путь.txt`. Путь может быть
относительным, абсолютным, содержать пробелы или `=`; расширение — именно `.txt`.
Например, `'--output=мой рисунок.txt'`. Формы `--output file.txt`, `-output=...`,
пустое имя, неизвестные или повторные флаги выводят приведённый Usage.

`--verify` и `--tamper-check` требуют `--output`. Флаги можно ставить перед
текстом или после него. Название шрифта идёт после текста. Разделитель `--`
завершает разбор флагов и позволяет рисовать текст, начинающийся с дефиса:

```sh
go run . --output=dashes.txt -- '--hello' shadow
```

Существующие исходные таблицы шрифтов `standard.txt`, `shadow.txt`, `thinkertoy.txt`
и пути внутри `.git` защищены от перезаписи программой. Таблица узнаётся по имени
и точному совпадению с встроенным оригиналом; обычный выходной файл с таким именем
в другом каталоге допустим. Символические ссылки, каталоги,
специальные файлы и существующие файлы без битов разрешения записи не принимаются
как выходной файл. Родительский каталог должен существовать.

## Проверка записанного файла: `--verify`

```sh
go run . --output=banner.txt 'hello' standard --verify
```

После успешной записи программа **повторно читает файл с диска** через
`os.ReadFile`. Проверяется именно прочитанное содержимое:

1. Файл существует, является обычным файлом и читается.
2. Количество строк равно `8 × количество текстовых строк`.
3. Все 8 строк внутри каждого блока имеют одинаковую ширину. Разные блоки могут
   иметь разные ширины.
4. Ширина каждой строки совпадает с шириной, рассчитанной по символам шрифта;
   лишних или удалённых столбцов и непечатных ASCII-байтов нет. Конечные пробелы
   рисунка сохраняются и считаются законными.
5. Размер равен сумме длин **прочитанных строк в байтах**, плюс один LF на строку.
   После последней строки тоже нужен LF.

Каждая успешная проверка даёт один балл: `5 → Valid`, `4 → Acceptable`,
`0–3 → Corrupted`. Это детерминированная проверка по правилам, названная AI
feature в ТЗ; нейросеть здесь не используется.

Для `hello` ширина равна 31: `8 × 31 + 8 = 256` байт. Вывод:

```text
File created: banner.txt

--- Verification Report ---
Integrity Score: 5/5 (Valid)

Checks:
  [PASS] File is readable
  [PASS] Line count is 8 (8 per row x 1 row)
  [PASS] Width consistent within each row (31)
  [PASS] No padding beyond row width
  [PASS] File size matches (256 bytes)
```

Некоторые иллюстрации `cat -e` в ТЗ показывают дополнительный `$`. В проекте
выбраны явно проверяемые требования: 8 строк и 256 байт для `hello`, без девятой
пустой строки. Несовпадение видимых символов при сохранённой геометрии может
получить `5/5`: для проверки точного содержимого предназначен следующий бонус.

## Бонус: поиск изменений `--tamper-check`

Сначала создайте файл, затем проверяйте его:

```sh
go run . --output=banner.txt 'hello' standard
go run . --output=banner.txt 'hello' standard --tamper-check
```

Программа заново генерирует рисунок в памяти, читает **существующий файл** и
сравнивает строки, включая конечные пробелы и завершающий LF. Она не записывает
файл перед сравнением и не исправляет его. Иначе изменение было бы затёрто.
Отсутствующий файл возвращает ошибку и не создаётся.

```text
--- Tamper Check ---
Result: file matches a fresh regeneration (unmodified)
```

Если поменять один символ четвёртой строки:

```text
--- Tamper Check ---
Result: 1 line differs from a fresh regeneration
  Line 4 differs
```

Для проверки и структуры, и точного содержимого существующего файла:

```sh
go run . --output=banner.txt 'hello' standard --verify --tamper-check
```

Это сравнение с текущим вводом и шрифтом, а не криптографическая подпись или
история изменений. Другой ввод также даст список отличающихся строк.

## Как сохраняется файл

Пакет `writer` проверяет цель, создаёт временный файл в том же каталоге,
записывает рисунок и проверяет ошибки записи, сохранения (`Sync`) и закрытия.
Только затем `Rename` атомарно заменяет целевой файл. При отказе до замены
существующие данные остаются на месте, временный файл убирается.
Новые файлы имеют права `0644`, у существующих сохраняются обычные биты прав.

Это защищает от частично записанного результата. Атомарная замена не обещает
сохранности после внезапного отключения питания и не блокирует другие процессы,
которые одновременно изменяют тот же путь. При одновременных успешных записях
остаётся целый результат последней замены.

Для предсказуемого расхода памяти установлены пределы: ввод до 1 МиБ, не более
10 000 текстовых строк, рисунок/проверяемый файл до 64 МиБ. Повреждённый файл с
более чем 1 048 576 строк отклоняется до разбиения на строки. Ошибка лимита
возвращается явно, результат не обрезается.

Коды завершения: `0` — успех, `1` — ошибка, обнаруженное изменение или хотя бы
одна проваленная проверка, `2` — неверные аргументы. `Acceptable` описывает 4 балла,
но код `1` всё равно сообщает автоматизации о неполном прохождении проверок.

## Структура

```text
symbol-output/
├── main.go, banners.go, main_test.go
├── go.mod
├── standard.txt, shadow.txt, thinkertoy.txt
├── internal/
│   ├── cli/          # аргументы, запуск, коды завершения
│   ├── generator/    # проверка таблицы шрифта и рисование
│   ├── writer/       # атомарная запись файла
│   └── verifier/     # пять проверок и сравнение изменений
├── test00.txt        # First\nTest, shadow
├── test01.txt        # hello, standard, ровно 256 байт
├── test02.txt        # цифры и специальные символы, standard
├── test03.txt        # Hello 01!, thinkertoy
├── scripts/audit.sh
└── docs/
    ├── AUDIT_REQUIREMENTS.md
    ├── AUDITOR_ANSWERS.md
    ├── FONT_SOURCES.md
    └── TEST_REPORT.md
```

Каждый пакет содержит тесты. Шрифты встроены стандартным `embed`: собранный
исполняемый файл работает из любого каталога, без соседних `.txt`.
Их оригиналы остаются в корне для аудита. Источники и контрольные суммы —
в [FONT_SOURCES.md](docs/FONT_SOURCES.md).

## Проверки и сборка

```sh
go fmt ./...
go test ./...
go test -race ./...
go vet ./...
sh scripts/audit.sh
go build -o /tmp/symbol-output .
/tmp/symbol-output 'hello'
```

Генеративные стресс-тесты запускаются отдельно:

```sh
go test ./internal/generator -run='^$' -fuzz=FuzzGenerate -fuzztime=10s -parallel=2
go test ./internal/verifier -run='^$' -fuzz=FuzzVerify -fuzztime=10s -parallel=2
```

Если учебная среда ограничивает запись в стандартный Go-кэш, добавьте
`GOCACHE=/tmp/symbol-output-go-cache` перед командой. Это настройка среды,
не зависимость проекта.

Готовые объяснения для разбора кода находятся в
[AUDITOR_ANSWERS.md](docs/AUDITOR_ANSWERS.md), соответствие пунктам ТЗ — в
[AUDIT_REQUIREMENTS.md](docs/AUDIT_REQUIREMENTS.md), результаты проведённых
проверок — в [TEST_REPORT.md](docs/TEST_REPORT.md).
